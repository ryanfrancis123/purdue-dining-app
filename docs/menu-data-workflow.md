# Menu Data Workflow

This document explains the current seed data workflow for the Purdue Dining App.

## Current source of truth

The current menu seed data lives in:

```txt
data/menu_items_seed.csv
```

This CSV is the source of truth for manually created seed menu rows.

## Validation

Before importing the CSV into Supabase, always validate it from the Expo app folder:

```bash
cd C:\Projects\PurdueDiningApp\app
npm run validate:menu
```

Expected output:

```txt
CSV validation passed.
```

Do not import the CSV into Supabase unless validation passes.

## Data report

After validation, you can generate a simple report to check whether the seed data is balanced:

```bash
cd C:\Projects\PurdueDiningApp\app
npm run report:menu
```

The report shows:

```txt
Total rows
Meal period counts
Category counts
Dining hall counts
Source counts
```

This helps confirm that the seed data has enough coverage across breakfast, lunch, dinner, categories, and dining halls before importing it into Supabase.

## CSV format rules

The CSV must include these columns:

```txt
name
dining_hall
meal_period
category
calories
protein_g
carbs_g
fat_g
allergens
dietary_tags
serving_size
source
is_active
```

The CSV should not include the `id` column.

The `id` column is automatically generated by Supabase/PostgreSQL using:

```txt
gen_random_uuid()
```

## Allowed values

Allowed meal periods:

```txt
breakfast
lunch
dinner
```

Allowed categories:

```txt
protein
carb
side
vegetable
fruit
dessert
drink
```

Allowed sources:

```txt
csv_seed
manual
purdue_menu
```

## PostgreSQL array fields

The `allergens` and `dietary_tags` columns use PostgreSQL array format.

Empty array:

```csv
{}
```

One value:

```csv
"{""milk""}"
```

Multiple values:

```csv
"{""vegetarian"",""vegan""}"
```

This quoting is required because commas inside arrays would otherwise break the CSV column structure.

## Clean reseed workflow

When updating seed data, do not blindly append rows in Supabase.

Use this workflow:

1. Edit `data/menu_items_seed.csv`.
2. Run validation:

```bash
cd C:\Projects\PurdueDiningApp\app
npm run validate:menu
```

3. Run the data report:

```bash
npm run report:menu
```

4. If validation passes and the report looks balanced, commit the CSV change.
5. In Supabase SQL Editor, check how many seed rows currently exist:

```sql
select count(*)
from menu_items
where source = 'csv_seed';
```

6. Delete only seed rows:

```sql
delete from menu_items
where source = 'csv_seed';
```

7. Import the full updated CSV into the `menu_items` table.
8. Confirm the new row count.
9. Test the app through Expo Go.
